◈ 8.1 I modelli del Cloud Computing
8.1 DEFINIZIONE E CARATTERISTICHE DEL CLOUD COMPUTING

Il cloud computing è la tecnologia che permette di archiviare, elaborare e usare applicazioni e risorse software messe a disposizione da un fornitore di servizi via Internet. È la conseguenza dell'evoluzione dei data center virtualizzati e delle tecnologie Web.

Il NIST (National Institute of Standards and Technology) ha definito il cloud computing in 5 caratteristiche fondamentali (attributi dei servizi):

ATTRIBUTODESCRIZIONE
On demand self-serviceL'utente accede autonomamente alle risorse senza intervento umano del provider.
Broad network accessFunzionalità disponibili ovunque via rete, da dispositivi eterogenei (mobile, desktop).
Resource poolingRisorse fisiche e logiche organizzate in pool condivisi, assegnate dinamicamente.
Rapid elasticityRisorse assegnate/rilasciate elasticamente; l'utente percepisce capacità illimitata.
Measured serviceOgni servizio è misurabile e fatturato in base all'uso effettivo.

Il NIST identifica anche: Modello dei servizi (SaaS, PaaS, IaaS), Modello di distribuzione (pubblico, privato, ibrido, comunitario), Risorse (elaborazione, storage, reti, applicazioni), Organizzazione dell'infrastruttura (architettura distribuita, virtualizzazione).

◈ 8.2 Il modello dei servizi
8.2.1 SaaS · PaaS · IaaS

I servizi cloud sono aggregati in tre classi. Ogni modello implica un diverso livello di gestione tra cliente e provider.

IaaS — Infrastructure as a Service
  • Fornisce l'intera infrastruttura: VM, storage, rete.
  • Il cliente gestisce SO, middleware e applicazioni.
  • Massima flessibilità; richiede competenze sistemistiche.
  • Esempi: Amazon EC2, Microsoft Azure, Google Cloud, IBM Cloud, OpenStack.
PaaS — Platform as a Service
  • Fornisce una piattaforma completa: SO, linguaggi, database, API.
  • Il cliente si concentra sullo sviluppo delle applicazioni.
  • Nessuna gestione dell'infrastruttura hardware/software.
  • Esempi: Google App Engine, Azure App Service, IBM Cloud (PaaS), OpenStack.
SaaS — Software as a Service
  • Applicazioni pronte all'uso via browser.
  • Sicurezza e infrastruttura a carico del provider.
  • L'utente può solo configurare l'applicazione.
  • Esempi: Google Drive, Dropbox, Box.net.

8.2.2 MICROSERVIZI

Estendendo il concetto di SOA (Service-Oriented Architecture), i microservizi scompongono un'applicazione in tanti piccoli processi autonomi e isolati, ognuno con il proprio database e ciclo di vita.

  • Ogni microservizio è un'entità atomica indipendente che comunica con gli altri tramite API RESTful, indipendentemente dal linguaggio usato.
  • Si passa da applicazioni monolitiche (aggiornamento completo ad ogni modifica) a microservizi aggiornabili singolarmente.
  • Vantaggi: condivisione tra applicazioni, facilità di compilazione, test e aggiornamento, scalabilità granulare.
  • Svantaggi: un numero elevato aumenta il traffico di rete e richiede una gestione (orchestrazione) più complessa.
8.2.3 CONTAINER

Un container è un'unità standard di software che impacchetta il codice con le sue dipendenze in un ambiente isolato e indipendente, eseguibile in modo identico su qualsiasi macchina (a parità di kernel e CPU).

Invece di virtualizzare l'intero stack hardware (come le VM), i container virtualizzano a livello del sistema operativo, condividendo il kernel dell'host.

8.2.4 CaaS — CONTAINER AS A SERVICE

Il CaaS (Container-as-a-Service) è un modello di servizio che rende del tutto trasparente la creazione e l'orchestrazione dei container (nodi, distribuzione nei data center cloud).

  • Permette di usare i container senza gestire i dettagli sistemistici della loro creazione.
  • Le aziende si concentrano sulla scrittura del codice; le attività sistemistiche scompaiono progressivamente.
  • Esempi di piattaforme CaaS: Google Container Engine (GKE), Amazon EC2 Container Service (ECS), Microsoft Azure Container Service (ACS), IBM Container Service.
  • L'orchestratore (es. Kubernetes) distribuisce, bilancia i carichi, replica i container in «pod» e gestisce storage e rete ridondante.
◈ 8.3 I modelli di distribuzione
8.3 I QUATTRO MODELLI DI DISTRIBUZIONE DEL CLOUD

Il NIST definisce quattro modelli di distribuzione (deployment models) del cloud:

CLOUD PUBBLICO
  • Servizi aperti al pubblico, accessibili via Internet tramite piattaforma del provider.
  • Hardware e infrastrutture fisicamente nella sede del provider.
  • Vantaggi: costi ridotti (pay-per-use), scalabilità quasi illimitata, nessuna spesa di manutenzione, alta affidabilità.
  • Svantaggi: nessun controllo diretto sull'infrastruttura; rischi di privacy; non sempre possibile scambiare dati tra fornitori.
  • Esempi: Azure (Microsoft), AWS (Amazon), GCP (Google), IBM Cloud.
CLOUD PRIVATO
  • Servizi riservati a una specifica azienda; infrastruttura (fisica o virtuale) gestita in rete privata.
  • Hardware e software dedicati esclusivamente all'organizzazione.
  • Vantaggi: massimo controllo e sicurezza, personalizzazione, scalabilità paragonabile al pubblico.
  • Svantaggi: non facilmente accessibile a utenti esterni; costi di gestione più elevati.
  • Soluzioni comuni: OpenStack (open source), VMware (proprietario).
CLOUD IBRIDO
  • Combinazione di cloud privato e pubblico, usati in modo complementare.
  • Vantaggi: controllo e sicurezza del privato + flessibilità del pubblico; migrazione graduale; convenienza (potenza aggiuntiva pagata solo quando serve).
  • Casi d'uso tipici: dati sensibili su cloud privato, email/app su cloud pubblico; picchi di accesso gestiti col cloud pubblico.
  • Multi-cloud: uso di più cloud pubblici di fornitori diversi per evitare dipendenza da un singolo ente.
  • Rischio: piattaforme eterogenee difficili da integrare; applicazioni personalizzate su piattaforme specifiche.
CLOUD COMUNITARIO
  • Simile al cloud privato, ma riservato a una comunità di organizzazioni con interessi comuni (stessa politica aziendale, requisiti di sicurezza, ecc.).
  • Può essere di proprietà dell'organizzazione o di un provider esterno.
