◈ 2.1 DNS – Domain Name System
2.1 DNS – DOMAIN NAME SYSTEM

Il DNS (Domain Name System) è stato creato per convertire gli indirizzi IP numerici in nomi semplici e riconoscibili (es. www.wikipedia.it invece di 91.198.174.192). Funziona come una rubrica mondiale automaticamente aggiornata.

Il protocollo DNS è a livello applicazione e utilizza di default il protocollo di trasporto UDP sulla porta 53 (ma può usare anche TCP).

Il sistema DNS è un grande database distribuito organizzato in migliaia di server DNS in rete, che garantisce efficienza, affidabilità e robustezza. Non esiste un'unica macchina con tutti i nomi: ogni DNS ha autorità solo per il dominio di sua competenza.

2.1.1 · GERARCHIA DI DOMINIO

Il DNS assegna uno spazio gerarchico dei nomi alle risorse in Internet. La gerarchia è visualizzabile come un albero in cui ogni nodo corrisponde a un dominio e alle foglie corrispondono i calcolatori.

Le etichette si leggono da destra verso sinistra. Per esempio in www.iana.org:

  • org → dominio di primo livello (TLD)
  • iana → dominio di secondo livello
  • www → nome del server (host)

📌 Registrazione domini
I nomi devono essere accettati e associati a un indirizzo IP da ICANN (Internet Corporation for Assigned Names and Numbers). In Italia i domini .it sono gestiti dal NIC (organo del CNR, con sede a Pisa).
2.1.2 · RECORD DELLE RISORSE E MESSAGGI DNS

L'albero dei domini è diviso in zone. Ogni zona mantiene informazioni organizzate in record delle risorse nella forma:

<Name, Value, Type, Class, TTL>
TYPEDESCRIZIONE
AIndirizzo IPv4 del dispositivo
AAAAIndirizzo IPv6 del dispositivo
MXMail eXchange – nome del server di posta
NSAuthoritative Name Server – nome del server che sa risolvere i nomi del dominio

I messaggi DNS (sia richiesta che risposta) hanno lo stesso formato, composto da: Header, Question, Answer, Authoritative, Additional.

  • TTL (Time To Live): indica per quanto tempo il record è valido nella cache di un server
  • Class IN: indica che la classe è Internet
2.1.3 · STRUTTURA E INTERROGAZIONE DEL DNS

La struttura del DNS è simile a un file system ad albero. Alla radice ci sono i root name server (poco più di una decina nel mondo, per lo più negli USA). Essi contengono l'elenco dei server responsabili dei TLD.

Sequenza di una risoluzione DNS per www.paperus.com:

  1. Il computer (A) chiede l'IP al suo server DNS locale (B)
  2. Se il server locale non ha il record in cache, interroga un root server (C)
  3. Il root server restituisce l'indirizzo del server autoritativo per .com (D)
  4. Il server .com viene interrogato e risponde con l'indirizzo del server per .paperus (E)
  5. Il server .paperus restituisce l'IP dell'host www
  6. Il server locale salva il risultato in cache e lo restituisce al computer
💡 Comandi utili
ipconfig /displaydns → mostra la cache DNS locale (Windows) · ipconfig /flushdns → svuota la cache · nslookup [dominio] → interroga il server DNS e recupera record e indirizzi IP
◈ 2.2 La posta elettronica
2.2 LA POSTA ELETTRONICA

La posta elettronica è tra i servizi più antichi e stabili di Internet, fondamentale nelle attività aziendali per lo scambio di messaggi e file digitali. I protocolli usati (SMTP, POP3, IMAP) sono stati creati quando sicurezza e spam non erano priorità, ma nel tempo sono stati integrati con estensioni.

2.2.1 · CARATTERISTICHE DELLA POSTA ELETTRONICA

La posta elettronica è un mezzo di comunicazione asincrono: consente lo scambio anche se mittente e destinatario non sono connessi contemporaneamente.

  • Un client non invia direttamente al client remoto: si appoggia a un server che memorizza e inoltra i messaggi (store & forward)
  • Ogni casella di posta ha un indirizzo univoco: nome_mailbox @ nome_server
  • User Agent: programma usato dall'utente per comporre, inviare e ricevere messaggi
  • Transfer Agent: programma che trasferisce i messaggi tra server di posta
Invio
Protocollo SMTP – dal client al server del mittente, poi al server del destinatario
Ricezione
Protocolli POP3 o IMAP – dal server del destinatario al client del destinatario
📌 Webmail
Le applicazioni Webmail (es. Gmail) forniscono accesso alla casella di posta tramite Web da qualsiasi postazione. Sono considerate client di posta a tutti gli effetti.
2.2.2 · STRUTTURA DI UN MESSAGGIO

Un messaggio di posta elettronica è composto da tre parti:

Busta (Envelope)
Incapsula il messaggio. Contiene indirizzo mittente, destinatario, priorità, sicurezza. Usata dagli agenti per l'inoltro.
Intestazione (Header)
Informazioni di controllo in formato nome_campo: valore. Campi principali: From, To, Subject, Date, Cc, Bcc, Reply-to
Corpo (Body)
Testo del messaggio destinato al lettore. Codificato in ASCII a 7 bit o MIME per allegati multimediali.
2.2.3 · MIME – Multipurpose Internet Mail Extensions

Il formato originale ASCII era inadeguato per lettere accentate, alfabeti non latini e allegati multimediali. MIME (RFC 1521, RFC 822) estende il formato dei messaggi mantenendo la compatibilità ASCII.

Nuove intestazioni introdotte da MIME:

  • MIME-Version: indica che il messaggio è in formato MIME (es. MIME-Version: 1.0)
  • Content-Type: specifica la natura del body (es. text/html, text/plain, image/jpeg)
  • Content-Transfer-Encoding: identifica la codifica dei dati (es. base64)
  • Content-Description: descrizione testuale del contenuto
  • Content-ID: codice identificativo del contenuto
📌 MIME e HTTP
Il campo Content-Type è usato anche come metainformazione nel protocollo HTTP.
2.2.4 · PROTOCOLLO SMTP

SMTP (Simple Mail Transfer Protocol, RFC 5321) si occupa di stabilire la connessione tra mittente e destinatario e trasferire il messaggio. Lavora sulla porta 25, usa TCP come trasporto.

Il protocollo si articola in tre fasi: apertura (handshaking) → trasferimento → chiusura.

Client e server comunicano tramite stringhe di testo: il client invia comandi di 4 caratteri, il server risponde con codici di stato a 3 cifre.

SERVER ›220 xyz.com SMTP ready// server pronto sulla porta 25
CLIENT ›HELO abc.com// saluto con nome mittente
SERVER ›250 xyz.com says hello...// confermato
CLIENT ›MAIL FROM: paolo@abc.com// mittente
SERVER ›250 sender ok
CLIENT ›RCPT TO: aaa@xyz.com// destinatario
SERVER ›250 recipient OK
CLIENT ›DATA// inizio dati
SERVER ›354 Start mail input; end with <CRLF>.<CRLF>
CLIENT ›<intestazione + corpo>
CLIENT ›<CRLF>.<CRLF>// fine messaggio
SERVER ›250 Mail accepted
CLIENT ›QUIT// chiudi connessione
SERVER ›221 xyz.com closing connection

ROUTING SERVER FAILUREIl dominio non esiste

MESSAGE TOO BIGIl messaggio supera il limite accettato dal server
2.2.5 · SMTP CON AUTENTICAZIONE

Il protocollo SMTP originale non prevedeva autenticazione, facilitando spam e phishing. L'estensione SMTP Service Extension for Authentication (RFC 4954) aggiunge un'autenticazione prima della connessione.

  • Si usa il comando EHLO (Extended Hello) invece di HELO per indicare il supporto alle estensioni
  • Il server risponde con l'elenco delle estensioni supportate (es. AUTH, LOGIN…)
  • Il client invia il comando AUTH LOGIN con username e password codificate in Base64
2.2.6 · PROTOCOLLO POP3

POP3 (Post Office Protocol v3, RFC 1939) permette al client di scaricare i messaggi dalla mail-box sul computer locale. Usa la porta 110 di TCP.

Si articola in tre fasi: apertura → trasferimento (autenticazione + transazione) → aggiornamento e chiusura.

COMANDODESCRIZIONE

⚠ Modalità download-and-delete
POP3 opera in modalità download-and-delete: dopo lo scaricamento, i messaggi vengono cancellati dal server e salvati solo localmente.
2.2.7 · IMAP – Internet Mail Access Protocol

IMAP è un'alternativa a POP3 (ideata da Mark Crispin nel 1986) che permette di gestire i messaggi direttamente sul server, senza necessariamente scaricarli in locale. È ideale per chi lavora in mobilità o usa più dispositivi.

  • I messaggi originali rimangono sul server fino alla cancellazione manuale
  • Mantiene la sincronizzazione tra client e server
  • Permette di leggere solo l'intestazione o parti del messaggio senza download
  • Usa la porta 143 (o 993 con SSL)

Comandi base IMAP:

COMANDOFUNZIONE
LOGINConnessione al server IMAP con credenziali
SELECTSelezione della cartella (es. INBOX)
SEARCHRicerca ed elenco messaggi con filtri
FETCHLettura del messaggio (o delle sue parti)
EXPUNGECancellazione definitiva dei messaggi con flag Deleted
⚖ POP3 vs IMAP
POP3: scarica e cancella dal server, adatto a un solo dispositivo, funziona offline.
IMAP: mantiene i messaggi sul server, adatto a più dispositivi, richiede connessione.
◈ 2.3 Protocollo FTP
2.3 PROTOCOLLO FTP – FILE TRANSFER PROTOCOL

FTP (File Transfer Protocol, RFC 959 – 1985) è un protocollo di livello applicativo usato per trasferire file su un server remoto. Utilizza due canali TCP distinti:

Canale di Controllo
Porta 21 – per l'invio dei comandi. Sempre attivo durante la sessione.
Canale Dati
Porta 20 (modalità attiva) – per il trasferimento dei file effettivi.

A differenza di HTTP, FTP permette di navigare nel file system remoto ed eseguire operazioni sui file (copia, cancellazione, spostamento, upload, download…).

2.3.1 · ACCESSO FTP
Accesso Autenticato
  • Username e password specifici
  • Accesso completo in base ai permessi
  • Autenticazione in chiaro → non sicuro
  • Versione sicura: FTPS (con SSL) o SFTP (via SSH)
Accesso Anonimo
  • Si digita "anonymous" come login
  • Nessuna password richiesta
  • Operazioni limitate (es. solo download)
2.3.2 · FUNZIONAMENTO – MODALITÀ ATTIVA E PASSIVA

Una sessione FTP si articola in quattro fasi: richiesta → autenticazione → trasferimento → chiusura.

FTP supporta due modalità per il canale dati:

Modalità Attiva
  • Il client invia al server il comando PORT con il numero di porta da usare
  • Il server avvia la connessione dati dalla sua porta 20 verso il client
  • Problema: il client potrebbe essere bloccato da un firewall
Modalità Passiva (consigliata)
  • Il client invia al server il comando PASV
  • Il server sceglie una porta casuale (1024–5000) e la comunica al client
  • È il client che apre la connessione dati → più sicuro con firewall
