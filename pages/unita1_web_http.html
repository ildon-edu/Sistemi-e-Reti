◈ 1.1 Il mondo di Internet
1.1 IL MONDO DI INTERNET

La fusione tra microelettronica e Internet ha generato una trasformazione senza precedenti nella storia umana. La tecnologia del silicio è diventata sempre più piccola, veloce ed economica (Legge di Moore), mentre Internet ha permesso uno scambio di informazioni senza limiti né barriere.

I dati raccolti da dispositivi e sensori vengono elaborati da motori software che cercano di estrarne il significato nascosto. Tecnologie come Cloud Computing, Internet of Things, Social Network, Machine Learning e Intelligenza Artificiale si sono già integrate nelle nostre abitudini.

⚠ Etica dell'IA
I sei pilastri dell'etica dell'Intelligenza Artificiale: equità, fiducia, privacy, inclusione, responsabilità, trasparenza. Le decisioni delle macchine si basano su algoritmi con potenziali rischi di parzialità.
◈ 1.2 La nascita del Web
1.2 LA NASCITA DEL WEB

Nel 1990, Tim Berners-Lee, ricercatore al CERN di Ginevra, propose un progetto per condividere informazioni in modo semplice e rapido tra ricercatori. I testi si trasformarono in ipertesti: nacque il World Wide Web.

  • HTML (HyperText Markup Language): linguaggio standard per le pagine Web
  • HTTP (HyperText Transfer Protocol): protocollo di comunicazione del Web
  • Nascono i primi browser per navigare in Internet
  • Il 30 aprile 1993 il CERN rende pubblico il software World Wide Web
  • Nel 1994 viene fondato il W3C (World Wide Web Consortium), la comunità che sviluppa gli standard Web
💡 Ipertesto
Un ipertesto è un documento consultabile in modo non lineare, passando da un punto all'altro tramite link (parole o immagini cliccabili). Un documento ipermediale è un ipertesto che include anche contenuti multimediali (audio, video, immagini).
◈ 1.3 Il livello di applicazione
1.3 IL LIVELLO DI APPLICAZIONE

Il livello di applicazione è il livello più vicino all'utente e funge da interfaccia tra le applicazioni software e i livelli sottostanti che permettono il transito dei messaggi in rete.

Nell'architettura TCP/IP questo livello ingloba i tre strati superiori del modello ISO/OSI (sessione, presentazione e applicazione), comprendendo formattazione dei dati, compressione e crittografia.

◈ 1.4 Funzionamento di un server Web
1.4 FUNZIONAMENTO DI UN SERVER WEB

Il server Web è l'applicazione software in esecuzione su un server che fornisce i contenuti Web richiesti. Il software sul server prende il nome di demone HTTP (HTTPd – HyperText Transfer Protocol Daemon).

Il demone è costantemente in ascolto (primitiva listen) di richieste dal client. Quando una richiesta arriva, cerca di soddisfarla individuando il file cercato e inviandolo al client con le relative metainformazioni.

Nei sistemi UNIX/Linux il demone può clonare se stesso generando un processo figlio identico, tornando subito in ascolto. Il figlio recupera il documento, lo invia al client e chiude la connessione.

⬡ Pagina Statica
  • Il file HTML è già presente in memoria
  • Il server lo recupera e lo invia direttamente al client
  • Il contenuto non cambia mai
⬡ Pagina Dinamica
  • Il file HTML viene generato da uno script lato server
  • L'output varia in base ai parametri ricevuti
  • Linguaggi: PHP, ASP, JSP, Python
1.4.1 · ARCHITETTURA CLIENT-SERVER

L'architettura di un'applicazione di rete si basa sullo scambio di informazioni tra due soggetti: client e server.

  • Il client fa una richiesta di una risorsa: può essere un qualsiasi browser (Chrome, Firefox…)
  • Il server risponde tipicamente con un file HTML che il browser interpreta e visualizza
  • Il percorso per individuare le informazioni è specificato nell'URL
  • Client e server possono essere su macchine diverse o sulla stessa macchina
⬡ Architettura Three-Tier
Un'applicazione Web completa si struttura su tre livelli: 1. interfaccia utente (browser) · 2. logica di funzionamento (server Web) · 3. accesso ai dati (DBMS server). In ogni livello adiacente, il livello più vicino all'utente è sempre client, l'ultimo è sempre server.
◈ 1.5 Il protocollo HTTP
1.5 IL PROTOCOLLO HTTP

HTTP (HyperText Transfer Protocol), insieme a HTTPS (la versione sicura), è il protocollo che costituisce il fondamento della comunicazione del Web. Opera a livello applicazione nel modello client-server.

HTTP trasmette i dati in formato testuale (ASCII), servendosi dei protocolli IP (livello di rete) e TCP (livello trasporto). Una sessione si stabilisce con una richiesta di connessione TCP alla porta 80 (o 443 per HTTPS).

1.5.1 · URI e URL
  • URI (Uniform Resource Identifier): identifica univocamente qualsiasi risorsa tramite uno schema universale
  • URL (Uniform Resource Locator): sottoinsieme di URI che identifica l'indirizzo Web di una risorsa

La struttura di un URL si articola in tre parti fondamentali:

protocollo :// nome host / nome file Struttura completa: protocollo://host[:porta]</percorso>[?querystring][#fragment]

  • Il metodo da applicare alla risorsa
  • L'URI (identificatore della risorsa)
  • La versione HTTP (tipicamente 1.1)

Il server non conosce il contenuto di ciò che invia: è il browser che deve interpretare correttamente i dati e mostrarli all'utente.

1.5.4 · IL PASSAGGIO DI PARAMETRI

Le pagine dinamiche ricevono parametri dal client nella forma:

parametro1=valore1&parametro2=valore2&parametro3=valore3

Il server legge la stringa, effettua il parsing e utilizza i parametri in base alle necessità. Il metodo di passaggio (GET o POST) determina dove viene inserita la stringa.

1.5.5 · I METODI GET E POST
⬡ GET
  • I parametri sono aggiunti all'URL dopo il carattere ?
  • I parametri sono visibili nella barra degli indirizzi
  • Lunghezza massima della stringa: 2048 caratteri
  • Il server legge la variabile di ambiente QUERY_STRING
http://server/script.php?classe=2B&sesso=M
⬡ POST
  • I parametri vengono inseriti nel body della richiesta HTTP
  • I parametri non sono visibili nella barra degli indirizzi
  • Nessun limite predefinito alla lunghezza dei dati
  • Ammette anche valori binari

Il server legge da standard input un numero di caratteri pari a CONTENT_LENGTH.

◈ 1.6 Considerazioni finali
1.6 CONSIDERAZIONI FINALI SU HTTP
CARATTERISTICADETTAGLIO
Stateless (senza memoria) Ogni richiesta è trattata dal server come unica e indipendente. I problemi vengono risolti con cookie e sessioni.
Asimmetrico (pull-based) Solo il client può chiamare il server. Non esiste la possibilità inversa.
Non sicuro Le richieste passano in chiaro. Le credenziali possono essere intercettate. Soluzione: HTTPS con crittografia SSL.
HTTP 1.1 (1997) Introduce le connessioni persistenti: più richieste su una singola connessione TCP (default mode).
HTTP/2 (2015) Pubblicato come RFC 7540. Permette richieste parallele senza attendere le risposte precedenti (eliminando il processo seriale di HTTP/1.1).
🔒 HTTPS
HTTPS usa gli stessi metodi di HTTP ma le richieste e le risposte sono crittografate tramite il protocollo SSL (Secure Socket Layer). Usa la porta 443. Comporta un carico di elaborazione aggiuntivo ma rende sicura la comunicazione.
